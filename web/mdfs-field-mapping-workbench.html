How auto-suggest scores a match

Every candidate blends five signals into one confidence — no single one is trusted alone. This is the same ensemble idea used in automated schema matching: normalized-name equality, Jaro-Winkler / token overlap for abbreviations (Qty→quantity), a domain synonym book (EPD work order name→FSM job number, amt→total amount), and value profiling (a column of dates → a date field). Suggestions never overwrite a field you’ve already confirmed.

📄 Running this from a SharePoint folder

This is a single, fully self-contained .html file — no server, no internet, no libraries. Everything (styles, logic, seed data) lives inside it, so it works from anywhere.

To use it

  1. Upload mdfs-field-mapping-workbench.html to your SharePoint document library.
  2. Because modern SharePoint may not render HTML pages inline (a tenant security setting), the reliable path is: select the file → Download → open it in Edge or Chrome. It opens instantly and works offline.
  3. Your edits auto-save to this browser. To make the mapping the shared source of truth, click Export JSON and keep that .json next to the HTML in the SharePoint folder. Anyone can Import it to pick up where the team left off.

Tip: keep one “master” JSON in SharePoint and version it there — that avoids the “which Excel is current?” problem from the workshop.

Scope

Three canonical models — Service Order (INT-21), WBS (INT-22), Procurement (INT-23) — each with an Inbound tab section (MDFS → Canonical → S4HC) and an Outbound section (S4HC → Canonical → FSM status callback). Use the Inbound / Outbound toggle on each model tab. Fields are the real Apollo catalogue; the JAMS reference is shown to guide the MDFS mapping.

Workflow that matches the workshop

  1. Sample Data tab → paste an MDFS extract → Profile & auto-suggest (fills the Inbound canonical fields with a best-guess MDFS source + confidence).
  2. On each model tab → turn on Mandatory only, confirm the self-explanatory suggestions, and set the rest to needs lookup or open question with an owner.
  3. Switch to Outbound ↑ to capture the FSM transport (REST callback / Platform Event / file) for each S4HC status field.
  4. Open Items tab → hand that list to Adrian / Karan; close them as answers come back.

Golden rules captured from the session

  • Always record the technical / back-end name — logical screen names differ and cause rework.
  • Flag lookups (linked objects like EPD name, the 19-digit Helix task number) — they need a join, not a direct map.
  • Client reference = the 19-digit task number quoted on claims — not the subcontractor claim ID, and not the “garbage” client contract ID.
