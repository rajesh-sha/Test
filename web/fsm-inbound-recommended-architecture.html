Delivery ladder — a per-FSM setting, not a per-FSM architecture

Every FSM lands on one rung. All four rungs are served by the same distribution layer.

What Apollo builds, runs and gains

Build

One distribution spine in CPI: delta poller + watermarks, canonical envelope, subscription registry, router, per-FSM queues, thin adapters. Reuses the passthrough APIs, canonical model, JMS and error logging already designed.

Run

One team, one toolset, one monitoring pane for both legs. Per-FSM queues isolate outages; DLQ alerts route to the owning FSM support team; replay covers recovery and initial loads.

Onboard

New or acquired FSM = assess against the ladder, add registry rows, one adapter, initial-load window, verify. Weeks of CPI work; FSM effort limited to credentials and field mapping.

Sequencing: JAMS day-one scope (spine + JAMS adapter) is complete without Advanced Event Mesh — the AEM entitlement question improves freshness later but gates nothing.
